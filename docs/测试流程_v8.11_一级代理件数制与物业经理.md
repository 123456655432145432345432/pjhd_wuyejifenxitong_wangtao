### 2.2 账号与数据（缺一不可）
| 用途 | 账号要求 |

## 六、回归风险点（重点看这几处）

1. **侧栏菜单顺序**：`propertyManagerMenus` 插在住户菜单**之前**，需确认住户原有菜单未被遮挡或丢失。
2. **「一级代理」命名混淆**：`individual-leaders`（个体负责人）与商家 `is_distributor`（一级代理）同名不同义，验收时确认业务方理解一致。
3. **提现审批菜单名称**：入口叫「配送员提现审批」，但该页现同时承载物业经理等**多角色**提现；如有需要建议改为「角色提现审批」以免误解（仅文案，非本次必改）。
4. **`GET /admin/distributor-products` 口径收紧**：老数据（关联商家未开通一级代理）将不再出现在列表，属后端预期行为，不是前端 Bug。
5. **`/auth/profile` 无 `isPropertyManager`**：入口依赖 `GET /property-managers/my` 探测，若测服该接口异常会导致经理菜单不显示——排查时先看该接口。

## 附录：接口自测（curl，绕过页面直验后端）

```bash
BASE=https://test.yuanxusoftware.top/api/v1
TOKEN=<你的管理端 access_token>

# 经理列表
curl -s "$BASE/admin/property-managers?page=1&pageSize=20" -H "Authorization: Bearer $TOKEN"

# 指派经理
curl -s -X POST "$BASE/admin/property-managers" -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"residentId":"res_1001","commissionRate":0.2,"status":"active"}'

# 开通 / 取消一级代理
curl -s -X POST "$BASE/admin/distributors/mch_xxx/enable"  -H "Authorization: Bearer $TOKEN"
curl -s -X POST "$BASE/admin/distributors/mch_xxx/disable" -H "Authorization: Bearer $TOKEN"

# 新建货源商品（必须带 distributorMerchantId，否则 60031）
curl -s -X POST "$BASE/admin/distributor-products" -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"distributorMerchantId":"mch_xxx","name":"测试货源","wholesalePrice":10,"suggestedRetailPrice":15,"stock":100}'

# 经理工作台（需住户 token）
curl -s "$BASE/property-managers/my" -H "Authorization: Bearer <resident_token>"
```

**关键错误码速查**

| 码 | 含义 |
|---|---|
| 60030 | 该商家未开通一级代理权限 |
| 60031 | 必须指定一级代理商家（distributorMerchantId） |
| 91005 | 物业经理不存在 / 当前用户不是在职经理 |
| 91006 | 该物业公司已存在在职物业经理 |
| 91007 | 物业经理身份已停用 |
| 91008 | 物业经理不可修改自己的分成比例 |
