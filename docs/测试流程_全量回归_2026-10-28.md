## 1. 门禁检查（每次提测前 3 分钟）

```bash
npm install                 # 首次或依赖变更后
node scripts/audit-router-menus.mjs   # 期望：ERROR 0 项，WARN 0 项
node scripts/audit-dead-actions.mjs   # 期望：0 个未引用动作函数（已达 0）
node scripts/audit-table-columns.mjs  # 期望：0 处列数不一致（已达 0）
npx vue-tsc --noEmit -p tsconfig.app.json   # 期望：无输出（当前 75 项，见第 7 节 D-00）
npx vite build              # 期望：built in ~7s，无 error
npm run dev                 # http://localhost:3000
```

判定：

- 第 2、5 条是真正的门禁：必须 0 错误才允许进入功能回归。
- **不要用 `npm run build` 判断类型是否干净**：它内部的 `vue-tsc` 不检查源码，永远退出 0。
- 第 3、4 条是本轮新增的只读审计（不改源码）：`audit-dead-actions` 抓「按钮没接上」，`audit-table-columns` 抓「表头比数据多一列」。两者都要求人工确认后再改代码，不能直接当结论。
- 第 6 条只验证「能打包」，不能替代第 5 条。
- 类型错误修完前，任何「已通过测试」的结论都要标注「类型门禁未启用」。
- 修 D-00 时把 `package.json` 的 `build` 脚本改成 `vue-tsc --noEmit -p tsconfig.app.json && vite build`（或 `vue-tsc -b`），闸门才会真正生效——这一步做完，历史构建记录里所有「✓」都要重新判定一次。

## 3. 角色准入矩阵（每类身份 5 分钟）

每类身份都按同一套 6 步执行，结果填入第 8 节记录表：

1. 手机号 + 密码登录 → 校验落地页与身份匹配（下表「落地页」列）。
2. 侧栏 / 移动端工作台菜单逐项展开 → 校验无越权项、无空分组、无重复项。
3. 逐个点击菜单 → 校验页面标题、首屏数据、无 403/9100x 报错。
4. 地址栏直访一条该身份**无权**的路由（如商家访问 `/param`）→ 期望被守卫弹回落地页，不出现白屏。
5. 刷新页面（F5）→ 期望留在原页面且登录态保持。
6. 退出登录 → 期望回登录页、`sessionStorage` 中 token 清空。

## 7. 缺陷分级与本次已确认问题

按「阻塞验收 / 影响功能 / 影响体验」三级记录。

### P0 阻塞验收（必须修完才能发版）

- **D-00 类型门禁失效 + 75 项类型错误**：`package.json` 的 `build` 是 `vue-tsc && vite build`，而 `tsconfig.json` 为 `files: []` + `references`，`vue-tsc --noEmit` 不解析任何源文件 → 退出码恒 0。用 `-p tsconfig.app.json` 才暴露 75 项错误 / 31 个文件（`vue-tsc -b` 报 76 项，多出 `vite.config.ts` 未纳入 `tsconfig.node.json`）。
