# 公开橱窗接口未加入免鉴权白名单

> **状态**：待后端
> **日期**：2026-10-28
> **入口**：管理端 → 住户菜单 → 公开橱窗（`/public/resident-shops`）及其详情页（`/public/resident-shops/:residentId`）
> **接口**：`GET /resident-merchants/public`、`GET /resident-merchants/public/{residentId}`、`GET /resident-merchants/public-listings`

## 现象

登录状态下点击「公开橱窗」，页面直接显示"Token缺失"，列表为空；改成未登录状态打开分享链接同样失败。

## 文档契约 vs 实测

API 文档三处均标注为公开/无需登录：

| 章节 | 接口 | 文档标注 |
| --- | --- | --- |
| §60.9.2 | `GET /resident-merchants/public` | **Auth**: Optional（无需登录） |
| §60.9.3 | `GET /resident-merchants/public/{residentId}` | **Auth**: Optional（无需登录） |
| §95.6 | `GET /resident-merchants/public-listings` | 鉴权：公开（`propertyCompanyId` 必填） |

实测（测试服 2026-10-28 21:34–21:46，未带任何请求头）：

```bash
# 1) 无 token
curl -s -o /dev/null -w "%{http_code}\n" \
  "https://test.yuanxusoftware.top/api/v1/resident-merchants/public?page=1&pageSize=5"
# → 401
# {"code":20001,"message":"Token缺失","timestamp":"2026-10-28 21:34:12"}

# 2) 带上非法 token
curl -s -H "Authorization: Bearer invalid.token.test" \
  "https://test.yuanxusoftware.top/api/v1/resident-merchants/public?page=1&pageSize=5"
# → 401 {"code":20003,"message":"Token无效"}

# 3) 同一路径族 public-listings
curl -s -o /dev/null -w "%{http_code}\n" \
  "https://test.yuanxusoftware.top/api/v1/resident-merchants/public-listings?propertyCompanyId=pc_demo001&page=1&pageSize=5"
# → 401 {"code":20001,"message":"Token缺失"}
```

## 定位结论

免鉴权白名单机制在后端是存在的，只是这三个路径没有进去。同批次对照测试（同样不带 token）：

| 接口 | 结果 |
| --- | --- |
| `GET /products?propertyCompanyId=pc_demo001` | **200** `{"code":0,...}` |
| `GET /merchants?propertyCompanyId=pc_demo001` | **200** `{"code":0,...}` |
| `GET /announcements?propertyCompanyId=pc_demo001` | 403 `20004 权限不足`（已被放行到业务层再拒，不是 token 缺失问题） |
| `GET /resident-merchants/public*` | **401 `20001 Token缺失`** |

即：网关先判断 token 是否存在（无 → 20001），再判断是否合法（非法 → 20003），只有命中白名单的路径才跳过这一步。`/products`、`/merchants` 已在白名单，`/resident-merchants/public*` 未在。

## 请后端处理

1. **将以下三个路径加入免鉴权白名单（仅 GET）**：
   - `/resident-merchants/public`
   - `/resident-merchants/public/{residentId}`
   - `/resident-merchants/public-listings`

2. **明确匿名访问时的租户口径**：无 token 则无法从身份中取 `propertyCompanyId`，请确认
   - 列表接口的 `propertyCompanyId` 是否改为**必填**（与 §95.6 的 `public-listings` 保持一致，避免跨物业串店铺）；
   - 若保持"可选"，不传时返回什么范围（全平台 / 默认物业 / 400）。当前前端未传该参数，请给出确定口径，前端按口径补传。

3. **自查同类接口**：文档中其它标注"公开 / Auth Optional"的路径是否都已在白名单（本次只验证了上述三个）。

## 前端已做 / 未做

**已做**（本轮已提交，`npx vite build` 通过）：

- `src/api/request.ts` 新增 `optionalAuth`：有 token 就带 `Authorization`，无 token 也照常发请求，失败只抛错不触发全局登出；
- `src/api/services.ts` 的 `listPublic` / `getPublic` 由"完全不带 token"改为"可选鉴权"（此前按文档传 `auth=false`，所以登录用户点开也必然 401）；
- 两个橱窗页对 `20001` 给出明确文案，不再直接显示后端原始 message。

**未做（依赖后端）**：

- 未登录访客访问仍需后端白名单放行，前端不构造本地假数据兜底；
- 白名单放开后再补 `propertyCompanyId` 传参（等第 2 点口径确认）。

# 期望：HTTP 200 + {"code":0,"data":{"list":[...]}}
