# 新建物业公司 — 唯一约束兜底 400（测服创建整体失败）

> **状态**：待后端（前端已排除请求体/字段重复问题）  
> **日期**：2026-09-07  
> **对照**：API v8.1 §14.3 / §51.2；《后端修复说明_2026-09-06》  
> **前端入口**：平台管理员 →「物业公司」→「新增物业公司」  
> **环境**：`https://test.yuanxusoftware.top`

---

## 1. 结论（请先看）

**任意全新、互不重复的公司名 / 联系电话 / 小区名 / 管理员手机号，创建一律 HTTP 400，`code=10002`，`message=数据已存在或违反唯一性约束…`。**

说明不是前端填了重复值，而是创建事务内某步（很像「初始化默认配置 / 积分池 / 配送规则」）触发了 **DataIntegrityViolation**，被兜底成这句文案。  
`POST /property-companies` 与 `POST /admin/property-companies` **两条路径同样失败**。

当前测服 **无法通过管理端新建物业公司**，也无法据此产出新的物业领导登录账号。

---

## 2. 复现（已在测服用超管 token 直连验证）

登录：`POST /auth/admin-login`，`13800138000` / `admin123456` → `code=0`。

### 2.1 纯 ASCII 唯一载荷（仍失败）

```http
POST /api/v1/property-companies
Authorization: Bearer <platform_admin>
Content-Type: application/json
```

```json
{
  "name": "pc_20260907082201",
  "contactPhone": "040020260907082201",
  "communities": [{ "name": "com_20260907082201" }],
  "adminAccount": { "name": "admin_20260907082201", "phone": "13907082201" }
}
```

响应：

```json
{
  "code": 10002,
  "message": "数据已存在或违反唯一性约束，请检查名称/手机号等是否重复",
  "timestamp": "2026-09-07 08:22:00"
}
```

同批列表 `GET /property-companies?page=1&pageSize=3&sort=-createdAt` 仍只有历史种子公司（如 `pc_baid001` 等），**无新建记录**。

### 2.2 管理端等价路径（同样失败）

同一载荷 `POST /api/v1/admin/property-companies` → 同样 `10002` 兜底文案。

## 3. 请后端排查

1. 打开创建事务日志 / `DataIntegrityViolationException` 根因，看 **违反的表名 + 唯一索引名**（不要只返回兜底句）。
2. 重点查创建成功路径里「自动初始化」写入：
   - 默认分成 / 物业币 / 配送配置
   - `point_pools`
   - `delivery_rules`
   - 其它带全局唯一键、却未按新 `propertyCompanyId` 区分的种子行
3. 预检已通过时不应落到兜底；请区分：
   - 公司名 / 管理员手机冲突 → 明确文案
   - 初始化写库冲突 → 明确表/索引，或修初始化幂等
4. 修复后验收：任意唯一载荷 → `code=0`，返回 `id` + `adminAccount.initialPassword`，列表可见新公司。
