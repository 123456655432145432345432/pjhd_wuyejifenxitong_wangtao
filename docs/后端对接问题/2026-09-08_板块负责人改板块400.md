# 板块负责人改板块：除保洁外 PUT 400

> **状态**：后端已修（API v8.3），待测服验收  
> **日期**：2026-09-08  
> **入口**：统筹 → 板块管理 → 编辑 → 改「负责板块」  
> **接口**：`PUT /admin/sector-leaders/{id}`（例：`sl_001`）  
> **对照**：API v8.3 §39；修复说明《2026-09-08_板块与特惠_后端修复说明》§1  
> **根因**：后端旧白名单与五枚举仅 `cleaning` 重合；现已统一 `cleaning/repair/security/greening/other`，并支持中文入参与冲突文案

## 现象

- 将板块改为 **保洁 `cleaning`** → 可保存成功  
- 改为 **维修 / 安保 / 绿化 / 其他** → **HTTP 400**  
- 浏览器：`PUT /api/v1/admin/sector-leaders/sl_001` → 400 Bad Request  

前端已对 `sector` 做归一化（中文「维修」→ `repair` 等），**不再提交中文**。仍仅保洁可通过，更像后端业务校验（唯一约束或枚举白名单），而非前端枚举写错。

## 复现

1. 统筹账号（持有 `sector.manage`，且 `sl_001` 挂在本人名下）  
2. 打开「板块管理」→ 编辑 `sl_001`  
3. 下拉选择「维修」→ 保存  
4. 网络面板看 Request Body 与 Response  

**请把 Response 的 `code` / `message` / `traceId` 回填本文档**（前端页面会展示 `message`）。

## 前端实际提交（期望）

```http
PUT /api/v1/admin/sector-leaders/sl_001
Authorization: Bearer <coordinator_or_admin_token>
Content-Type: application/json

{
  "sector": "repair",
  "description": "…",
  "status": "active"
}
```

合法 `sector` 集合（与 §39.2 / §39.4 / 申请接口一致）：

| 值 | 含义 |
|----|------|
| `cleaning` | 保洁 |
| `repair` | 维修 |
| `security` | 安保 |
| `greening` | 绿化 |
| `other` | 其他 |

## 可能根因（请后端逐项确认）

| # | 假设 | 如何验证 | 期望处理 |
|---|------|----------|----------|
| 1 | **同物业同板块唯一**：已存在另一条 `sector=repair` 的启用板块负责人，改 `sl_001`→`repair` 冲突 | 查库 `sector_leaders` where property + sector + active | 返回 **400**，message 明确：「该物业下维修板块已有负责人 xxx，请先撤销或改其板块」；**不要**笼统写「sector不合法」 |
| 2 | **demo 数据 `sl_001` 写死只能 cleaning** | 用新建的 `sl_` 改 repair 是否成功 | 去掉写死；或文档注明 demo 限制 |
| 3 | **枚举校验只放行了 cleaning**（代码/字典漏项） | 单测 `repair`/`security`/`greening`/`other` | 与文档五枚举对齐 |
| 4 | **统筹只能改描述、不能改板块** | 产品确认 | 文档写清；403/400 message 区分「无权限改板块」vs「值非法」 |
| 5 | 误把 `sectorName` 中文当校验源 | 日志打印入参 | 只校验 `sector` 英文码 |

> 若 message 已是「板块不合法」但 body 已是 `repair`，请查校验器是否读错字段或用了旧枚举表。

## 期望契约

1. `PUT` 允许在五枚举间切换（在权限与唯一约束允许时）。  
2. 唯一冲突时：**专用文案**（含冲突对象 id/姓名/原板块），错误码可用 `10002`，但 message 必须可运营理解。  
3. 真正非法值（如 `foo`、空串）才报「sector不合法」。  
4. 响应示例（冲突）：

```json
{
  "code": 10002,
  "message": "该物业下板块「repair」已有启用中的负责人 sl_xxx（张三），请先调整后再改",
  "data": null
}
```
