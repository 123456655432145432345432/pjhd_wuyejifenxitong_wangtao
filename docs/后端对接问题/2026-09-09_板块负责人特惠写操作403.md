# 板块负责人创建/删除特惠 403 权限不足

> **状态**：后端已修（API v8.4），待测服验收  
> **日期**：2026-09-09  
> **账号**：`role=sector_leader`  
> **入口**：板块负责人工作台 → 板块特惠 → 新建 / 删除 / 发布 / 下架  
> **接口**：`POST/PUT/DELETE /special-offers`、`GET /special-offers/{id}`、`POST .../publish|unpublish`  
> **对照**：API v8.4 §25；[`2026-09-09_履约链路与板块特惠_前端交付说明.html`](../功能完成度与测试清单_对照API_v8.4_2026-09-09履约与板块特惠.md) §3.7  
> **关联**：[`2026-09-07_统筹特惠与板块写操作403.md`](./2026-09-07_统筹特惠与板块写操作403.md)（v8.2 只放行了 coordinator）

## 原现象

板块负责人发/改/删特惠 → `403 20004`。统筹不受影响。根因：`sector_leader` 与 `coordinator` 共用权限分支，最终落到 `requireAdmin()`，只放行物业/平台。

## 后端已实现（v8.4）

| 接口 | 结果 |
|------|------|
| `POST/PUT/DELETE /special-offers` | ✅ `sector_leader` 按角色放行，**不要求** `promotion.push` |
| `GET /special-offers/{id}` | ✅ 补放行（此前看自己发的详情会 403） |
| `POST .../publish`、`.../unpublish` | ✅ Roles 补上 `sector_leader` |
| 数据范围 | 仅本人物业；越权 → `404 90001`「特惠不存在」 |
| `publisherRole` | 可为 `sector_leader`；住户端可见性不按发布者角色过滤 |

## 前端对接

| 项 | 说明 |
|----|------|
| 路径 / body | **不用改**，本来就调 `/special-offers` |
| 已做 | 板块特惠页文案标明 v8.4 按角色放行；错误直接展示后端 `message`（含 90001） |
| 住户端 | 无需为本次 403 改接口；发布为 `published` 后按 §25.6 可见 |

## 测服验收

1. 部署 v8.4 + 执行履约/特惠相关 SQL（若尚未执行）  
2. 板块负责人：新建已发布 → **200**；草稿 → 立即发布 → **200**；下架/删除 → **200**  
3. 同物业住户 `GET /special-offers` 能看到已发布条  
4. 故意越权 → **404 90001**，不是接口坏了
