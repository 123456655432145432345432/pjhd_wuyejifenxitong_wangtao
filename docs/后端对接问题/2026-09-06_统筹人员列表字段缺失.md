## 3. 后端需修复

### P0 — 列表 / 详情补齐关联字段

创建 `GET /admin/coordinators`、`GET /admin/coordinators/{id}` 的 VO：

1. **关联住户**：填充 `residentId`、`residentName`、`residentPhone`（勿只回裸 `phone`，或二者都给且一致）。
2. **关联物业**：填充 `propertyCompanyId`、`propertyCompanyName`。
3. **时间**：填充 `createdAt`（格式与其它管理端列表一致，如 `yyyy-MM-dd HH:mm:ss`）。
4. **商家数**（建议）：`merchantCount` — 该统筹管辖范围内商家数量；暂无则回 `0`，不要省略导致前端「—」。

### P1 — 字段名稳定

- 对外统一 **camelCase**（与 v7.1 示例一致）。
- 若暂时保留 `phone` / `name` 别名，请同时提供文档字段 `residentPhone` / `residentName`。

### P2 — 数据完整性

- 种子 / 历史数据若缺 `resident_id` 或物业绑定，列表也应能区分「未绑定」与「查询未 join」；当前表现为整列空白，无法运营。
