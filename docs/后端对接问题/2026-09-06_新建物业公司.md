## 2. 契约（v7.1）

### 2.1 推荐路径

| 路径 | 文档 | 说明 |
|------|------|------|
| `POST /property-companies` | §14.3 | 前端**当前使用**（同前缀列表接口，避免 `/admin/**` 权限拦截器问题） |
| `POST /admin/property-companies` | §51.2 | 管理端等价接口；Roles 仅 `platform_admin` |

§51.2 请求体必填（前端已按此校验）：

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | ✅ | 物业公司名称 |
| `contactPhone` | ✅ | 公司联系电话 |
| `address` | ❌ | 地址 |
| `communities` | ✅ | 至少 1 个小区 |
| `communities[].name` | ✅ | 小区名称 |
| `communities[].totalBuildings` / `totalUnits` | ❌ | 统计字段，不生成房号 |
| `adminAccount.name` | ✅ | 初始管理员姓名 |
| `adminAccount.phone` | ✅ | 初始管理员手机号（登录账号） |
| `adminAccount.email` | ❌ | 邮箱 |

### 2.2 前端实际请求示例

```http
POST /api/v1/property-companies
Authorization: Bearer <platform_admin token>
Content-Type: application/json
```

```json
{
  "name": "测试物业A",
  "contactPhone": "0427-1234567",
  "communities": [
    { "name": "测试花园" }
  ],
  "adminAccount": {
    "name": "张三",
    "phone": "13812345678"
  }
}
```

说明：

- 楼栋数 / 户数为 `0` 时前端**不传**对应字段（避免脏 0）。
- **不要**依赖 Query `propertyCompanyId`（创建新公司无关当前登录挂接的物业）。

| 4 | `POST /property-companies`（必填齐全）→ **500「内部服务异常」** | **后端未捕获异常**（文档：系统异常统一该文案 + `traceId`） | 仅能提示换未占用手机号、复制 `traceId` |

## 4. 后端需排查 / 修复

### P0 — 创建接口 500

1. 用平台管理员（如文档账号 `13800138000`）调用 §2.2 示例，查服务端堆栈与 Response 中的 `traceId`。
2. 常见嫌疑（请逐项确认）：
   - `adminAccount.phone` **已存在**（演示号如 `13900001111`、`13800138000`、`13900000020` 等）→ 唯一约束未转业务错误，直接 500。
   - 创建时初始化默认分成 / 积分 / 结算配置 **NPE**。
   - 同时建小区 + 管理员账号事务中途失败未回滚清晰报错。
3. **期望**：业务问题返回 **HTTP 400** + 明确 `message` / `errorCode`（如手机号已占用、名称重复）；仅真正系统故障才 500。

### P1 — 双路径行为一致

| 项 | 期望 |
|----|------|
| `POST /property-companies` 与 `POST /admin/property-companies` | 同一套校验与创建逻辑，或文档标明废弃其一 |
| `/admin/**` + PermissionInterceptor | 若保留 admin 路径，需保证 `platform_admin` 有对应权限项，勿误 401 |
| Query `propertyCompanyId` | 创建接口应忽略；附带时不应 500 |

### P2 — 错误可观测性

- 500 响应保留 `traceId`（文档已要求）。
- 手机号冲突、名称重复等给出稳定 `errorCode`，便于前端精确提示（勿一律「内部服务异常」）。
