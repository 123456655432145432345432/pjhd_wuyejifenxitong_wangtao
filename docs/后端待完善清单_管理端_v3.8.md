## 一、现状说明（前端已做 vs 卡在后端）

| 现象 | 原因 | 前端现状 |
|------|------|----------|
| 住户列表仍像按注册时间排 | `GET /residents` 的 `sort` 默认 `-createdAt`，`building,unit,room` 多半被忽略 | 当前页前端兜底：有地址在前，未填写显示「未填写」并靠后；**跨页全局排序需后端** |

| 参数页「按重量加价」「默认积分兑换」改完保存变回 0 | §51.6 `PATCH .../config` **未收录**这些字段，后端忽略 | 输入已禁用并提示，避免误以为可保存 |

## 三、物业公司配置（参数配置页）

对照 **§51.6** `PATCH /admin/property-companies/{id}/config` 当前契约，下列字段**未收录**，保存无效：

| 优先级 | 字段 | 说明 |
|--------|------|------|
| P0 | `deliveryPerKgFee` / `perKgFee` | 按重量加价（元/kg）；需写入 config，且 GET 详情/config **回显** |
| P0 | `pointExchangeRate` | 物业级默认「1 元 = X 积分」；需写入 config 并回显（与商家级批量配置区分） |
| P1 | 平台分成三项 | `platformShareRate`、`platformDeliveryShareRate`、`platformWithdrawalFeeShareRate`：明确是纳入本 config，还是仅走 `/admin/platform-share-rates` |
| P0 | 物业币使用条件 | §79：`PUT /admin/property-companies/{id}/coin-use-condition`（`point_threshold` / `property_fee_paid` / `manual_issue`） |
| P0 | 提现机制增强 | §80：`GET/PUT /admin/coin-withdrawals/settings`；阻止/解阻止居民、商家提现 |

**§51.6 已支持、前端已对接（无需重复开发，仅需联调稳定）**：  
`propertyShareRate`、`coordinatorShareRate`、`sectorLeaderRate`、`individualLeaderRate`、币显示/发放/冻结默认、配送起步价与快递员报酬、提现手续费率、`pointToFeeRate`、`twoYearClearEnabled`、`neighborDailyContactLimit` 等。
