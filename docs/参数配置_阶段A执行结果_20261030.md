## 4. 需要后端处理的一处冲突：`97020` / `97021` 已被占用

后端 §1.3 把 `97020` / `97021` 定为「本小区未启用积分 / 物业币功能」。但前端现有错误码文案表里这两个数字码**已经是别的含义**：

| 位置 | 现值 |
| --- | --- |
| `src/api/request.ts` L58 | `97020: '订单已完成，不支持退款'` |
| `src/api/request.ts` L59 | `97021: '分账账户未就绪'` |
| `src/constants/enums.ts` L2526-2527 | 同上（第二份相同映射） |

如果按新口径直接覆盖，退款与分账场景的错误提示会变成「本小区未启用积分功能」，属于把错误信息指向错误模块。所以在后端确认前，**前端没有改这两个文案**。

需要后端二选一：

1. 换码（例如 `97040` / `97041`），前端只需在两张表各加两行；
2. 坚持 `97020` / `97021`，并明确原来的「订单已完成不支持退款」「分账账户未就绪」是否已废弃。若未废弃，前端无法用数字码区分，只能依赖 `errorCode` 字符串。

## 5. 验收步骤（可直接照做）

前置：后端 P0 已部署（详情返回 `pointEnabled` / `coinEnabled`）。

1. **平台关积分**：参数配置 → 选物业 → 关「启用积分功能」→ 保存 → 刷新，开关应保持关闭。
2. **落库已生效**：用一个住户账号调积分写接口（走小程序或 Postman），应返回 `97020`（若与第 4 条冲突未解决，按后端实际码核对）。
3. **物业领导范围**：物业领导登录 → 只能看本物业 → 关「启用物业币」→ 保存成功；分成比例与提现手续费为灰，无法输入。
4. **物业领导不带分成字段**：F12 看 `PATCH /admin/property-companies/{id}/config` 的请求体，**不应出现** `platformShareRate` / `propertyShareRate` / `withdrawalFeeRate`。
5. **平台带分成字段**：换平台账号保存，请求体应出现上述字段；三档合计不足 100% 时提示 97006。
6. **商城抵扣**：平台账号该三项为灰；物业领导可改并保存，请求打到 `PUT /admin/property-coin/mall-rules`。
7. **页面已下架项**：积分区不再有「积分分成比例」卡与「积分兑换比例」；分账区无「参考比例」折叠区；配送区无「按重量加价」；物业币区无「发放模式」「新用户默认冻结」。
