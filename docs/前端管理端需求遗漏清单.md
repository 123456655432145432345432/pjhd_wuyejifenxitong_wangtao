## 一、首页 UI（§1）

| 需求 | 状态 | 管理端现状 |
|------|------|------------|
| 官方推荐商家展示 | ✅ | `Merchant.vue` 可设官方推荐 / 推荐排序；接口 `merchantRecommendApi` |

## 二、配送体系（§2）

| 需求 | 状态 | 管理端 / 商家端现状 |
|------|------|---------------------|
| 满 X 元免配送（商家自设） | ✅ | `MerchantOverview.vue`：`deliveryFee`、`freeDeliveryThreshold` |
| 支付后自动进配送大厅 | ⚠️ | 商家订单页注释写明应自动发单，仍保留「发送配送任务」兜底；物业 `Delivery.vue` 为监控看板 |
| 小区内 / 外 + 1/3/5km / 全市 | ✅ | 枚举 `DELIVERY_SCOPE`、`DISTANCE_TYPE`；`MerchantServiceScope.vue` |
| 商家可组合配送方式 | ✅ | 小区内 + 小区外 → `both` |
| 配送费 / 门槛商家自有，物业只读 | ⚠️ | 物业商家详情只读 ✅；**统筹**审核 / 编辑仍可改配送费与满额门槛 ❌ |
| 配送成本从商家费用扣除 | ✅ | `Delivery.vue` / `Merchant.vue` / `Param.vue` 文案与利润流已体现 |

### 与需求矛盾

1. **统筹仍可改配送费**（`CoordinatorMerchants.vue` 编辑 / 审核表单）——应改为只读或删除字段。  
2. **物业菜单「配送价格区间」**（`DeliveryPriceRanges.vue`）可 CRUD 重量价 + 距离 / 范围——需求称配送模块不属于物业公司管理；需产品裁定：迁到平台端、改为只读，或明确「平台规则表 ≠ 商家配送费」。  
3. `Param.vue`「按重量加价」仍可由物业改——与「配送价商家自管」边界需澄清。

## 四、服务板块（§4）

| 需求 | 状态 | 现状 |

| 需求匹配 → 关键词触达 → 报价 | ⚠️ | 关键词：`MerchantKeywords.vue`（支持批量）；报价仍是**表单弹窗**（金额 / 币种 / 说明 / 有效小时） |

### 待产品确认（需求原文带 ?）

- **入驻后是否可直接在平台接单**：前端已有服务需求接单能力，需确认业务规则（审核通过即可接 / 需另开通服务类目等）。  
- **询价是否全面聊天化**：若确认，需废弃 `MerchantServiceRequests` 报价表单，改为会话发价 / 订单链接。

## 五、积分与物业币（§5）

| 需求 | 状态 | 现状 |
|------|------|------|
| 家庭积分（个人）+ 建设积分（集体） | ⚠️ | `Points.vue` 单一余额；`CommunityPoints.vue` 建设积分。**无**家庭 / 个人积分分栏 |
| 默认 1 元 = 1 积分，商家不可改 | ❌ | `Param.vue` 默认 `pointExchangeRate: 100`；商家文案「1元=100积分」；与需求 1:1 **直接冲突** |
| 积分仅可兑物业币，不可直接冻结积分 | ⚠️ | 有币发放 / 冻结；未见「积分只能兑币、不可兑现金」硬规则 UI；且仍有 `pointToFeeRate` 抵物业费 |
| 币使用条件 a / b / c | ✅ | `Param.vue` + `COIN_USE_CONDITION`（阈值 / 已缴物业费 / 手动配发） |
| 是否显示物业币余额 | ✅ | `coinDisplayEnabled` |
| 自动提现周期 + 阻止某用户提现 | ✅ | 提现设置 + 住户 / 商家详情「阻止提现」 |
| 提现界面数据看板风格 | ⚠️ | 商家 / 配送员提现页有汇总卡片；管理端审批页仍是列表 |
| 资料完善积分奖励（物业 / 社区 / 平台 / 统筹） | ⚠️ | `ProfileRewards.vue` 支持四 scope，但挂在**物业领导菜单**；统筹端**无入口** |

### 需求原文待澄清（§5.2）

「积分仅可兑换为物业币，不可直接冻结积分」与现有「冻结物业币 / 积分池」能力如何并存，需产品一句话定稿后再改 UI。

## 七、商家管理（§7）

| 需求 | 状态 | 现状 |
|------|------|------|
| 物业负责商家审批 | ⚠️ | API 有 `merchantApi.audit`；**`Merchant.vue` 无审核按钮**，仅筛选审核状态 / 踢出 / 推荐。实际审核在统筹 / 板块 |
| 查看积分额度、广告天数、配送信息 | ⚠️ | 配送只读 ✅；广告额度可查可加 ✅；商家积分额度 / 余额在物业详情中展示不完整 |
| 权重 / 排序物业可调 | ⚠️ | `rankOrder` 可编；`levelWeight` 只读展示 |
| 商品分类由平台设计 | ✅ | `PRODUCT_CATEGORY` 固定下拉 |
| 关键词 / 动态 / 产品 | ✅ | 商家门户对应页齐全 |

## 十一、建议补齐顺序（仅前端管理端）

### P0（与需求直接冲突或核心流程断点）

1. **下线咨询模块**：菜单、路由、移动快捷入口、相关文案。  
2. **兑换比对齐 1:1**：`Param.vue` 默认值、商家详情文案、`MerchantPoints.vue` 说明；锁定商家不可改。  
3. **明确商家审核归属**：物业 `Merchant.vue` 补审核，或文档改为「统筹审、物业只读」。  
4. **统筹去掉配送费 / 满额门槛编辑**，与物业只读策略一致。  
5. **双积分展示**：待后端字段后，在积分管理拆「家庭 / 个人」与建设积分。

### P1（权限与体验缺口）

6. 统筹：住户只读、提现、资料奖励入口；板块 / 区域提现门户。  
7. 服务询价改为聊天发价（或明确表单仅过渡方案）。  
8. 住户：物业费起止日期；排序纳入楼层（配合后端）。  
9. 裁定「配送价格区间」归属（平台 / 物业只读 / 保留）。

### P2（体验增强）

10. 图片真实上传（活动组封面、商品、动态）。  
11. 管理端提现审批看板化（盈利 / 可提现等）。  
12. 若需要：居民首页区块命名与官方推荐位的运营配置页。
