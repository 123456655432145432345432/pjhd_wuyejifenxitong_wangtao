分账逻辑说明

本文说明物业积分系统中的分账规则：哪些钱怎么分、积分怎么返、配置在哪里改、结果在哪里看。 系统里存在两套互不混用的逻辑——现金分账与积分分成（消费返积分）。

适用：管理端 / 统筹体系 / 平台 对照：参数配置 · 平台分成配置 · 分成记录 更新日期：2026-08-06

一、先分清两套逻辑

日常说的「分账 / 分成」在本系统里对应两套独立机制，配置页也是分开的，验收时不要混用。

套件 A · 现金

现金分账（订单分成）

第三方商家订单有可分配现金时，按比例切给平台、物业、统筹、板块负责人、个体负责人等。 对应参数页的「分账设置区」，以及平台的「平台分成配置」。

结果落在：分成记录 /distribution/records、平台收益等。

套件 B · 积分

积分分成（消费返积分）

按消费金额（或可分部分）的一定比例，把积分返到业主、商家、物业币、小区建设（共享）积分池。 对应参数页的「积分分成比例」。

结果落在：住户积分余额、商家侧积分、建设积分流水等。

不要混淆：「用积分付款」是在花掉积分余额；「积分分成」是消费后返还积分。 全额积分支付通常没有可分现金，现金分成记录可能为空——这是预期行为，不是分成坏了。

二、组织层级（分润落在谁身上）

现金分账的主链路与统筹体系一致：

物业公司
  └─ 统筹（可管多个小区）
       └─ 板块负责人（如保洁 / 维修等板块）
            └─ 个体负责人（管辖具体商家）

此外，系统还存在一套并行的区域负责人 → 项目负责人结构（管理端可维护 shareRate），与「个体负责人」并存。主分成记录展示目前仍以「物业 / 统筹 / 板块 / 个体 / 平台」为主。

产品含义：每一层拿的是「订单可分配金额」里属于自己的那一截现金收益，再通过各自门户提现（提现能力按角色开放，与分成入账是两件事）。

三、现金分账（订单分成）

3.1 触发条件

  • 第三方商户订单产生可分配金额（一般需有现金支付部分，且订单进入可结算状态，如完成后生成分成记录）。
  • 比例适用于「接入社区的第三方商户订单结算」（参数页分账区说明）。

3.2 计算顺序（核心）

  1. 确定可分配金额 记为 distributableAmount（分成记录里的「可分配金额」列）。
  2. 先抽平台订单分成 按 platformShareRate 从可分配金额中抽取平台收益。
  3. 剩余按四级权重分配 物业、统筹、板块负责人、个体负责人按各自配置比例（或相对权重）瓜分剩余部分。
  4. 落账并生成分成记录 各角色金额写入分成明细，可在统筹/管理端查看。 
可分配金额 distributableAmount
  │
  ├─ 平台订单分成 = 可分配金额 × platformShareRate
  │
  └─ 剩余 = 可分配金额 × (1 − platformShareRate)
       ├─ 物业       propertyShareRate（相对权重）
       ├─ 统筹       coordinatorShareRate
       ├─ 板块负责人 sectorLeaderRate
       └─ 个体负责人 individualLeaderRate

3.3 平台比例提高时会发生什么

在「平台分成配置」中提高订单分成比例后，物业 → 统筹 → 板块 → 个体四级的实际占比 会按原有权重等比压缩（页面有「按当前输入值估算的四级实际占比」预览）。

剩余可分比例 = 1 − 平台订单分成比例
某级实际占比 ≈ 该级原比例 × (剩余可分比例 / 四级原比例合计)

3.4 四级比例配置项

界面名称 典型字段 含义
物业分成 propertyShareRate 物业公司从订单分润中获得的比例/权重
统筹分成 coordinatorShareRate 统筹角色分润
板块负责人 sectorLeaderRate 板块负责人分润
个体负责人 individualLeaderRate 个体负责人分润
权限注意：产品要求「分成比例由平台统一管理」，但当前参数页「分账设置区」物业端仍可能可编辑四级比例； 平台三项（订单 / 配送 / 提现手续费）在参数页为只读，须到「平台分成配置」修改。若做权限收口，应以平台可写、物业只读为准。

四、平台三条收益链路

平台管理员不只抽「订单分成」，还有配送费与提现手续费两条独立链路。三者互不替代。

链路 配置项 基数 说明
订单分成 platformShareRate 订单可分配金额 默认可为 0%；提高后会压缩下级四级占比
配送费分成 platformDeliveryShareRate 配送费 从配送费中抽取；与订单商品分润分开
提现手续费分成 platformWithdrawalFeeShareRate 提现手续费 从提现手续费中抽取；默认常见为 100%

配置入口：侧边栏 平台分成配置（仅平台管理员可改）。参数配置页对平台管理员仅作只读展示。

查看入口：平台收益页（统计 + 明细记录）。

五、商家分成比例

商家详情/列表中的 commissionRate（商家分成比例）是商家与上级（板块 / 个体等）协商的比例， 与参数页「四级现金分账」不是同一组字段。

  • 设置入口：板块负责人 / 个体负责人的商家管理页「设置分成」。
  • 变更通常走价格审批，类型为 merchant_distribution（商家分成），审批通过后才生效。
  • 商家营收/利润空间展示中，也会按物业、统筹、板块、个体、平台等维度做收益拆分展示（展示用 breakdown）。
记忆法： commissionRate = 这家店怎么跟上级分； 参数页四级比例 = 整盘订单结算时各角色怎么分。

六、积分分成（消费返积分）

6.1 它是什么

物业在参数配置中设定：消费产生积分时，按多大比例分别进入四个去向。 四项合计不得超过 30%（单项也受 ≤30% 约束）。

界面名称 字段 积分去向
业主积分分成 residentPointShareRate 住户个人积分
商家积分分成 merchantPointShareRate 商家侧积分
物业币积分分成 coinPointShareRate 物业币相关部分
共享积分分成 sharedPointShareRate 小区建设（共享）积分池

6.2 它不是什么

  • 不是「用积分支付订单时再分一次账」。
  • 不是参数页「分账设置区」的现金分润。
  • 不是「积分抵扣物业费」比率（那是另一套配置）。

6.3 修改与生效

  • 前端表单用百分比录入，提交时转为 0 ~ 0.30 小数（例如 10% → 0.1）。
  • 禁止直接长期绕过审批乱改：变更须通过价格审批，itemType = resident_share_rate；物业领导或平台管理员审批通过后落库。
  • 后端校验：四项合计 > 0.30 应返回参数非法；前端也会拦截超限提交。
默认值提醒：新建物业公司时四个比例常默认为 0。 若不先改成非 0 并审批生效，订单完成也不会看到「返积分」效果。

七、一笔订单完整走法

用户下单并完成履约/确认
│
├─ 有可分现金？
│    是 → 生成现金分成记录
│         （平台 / 物业 / 统筹 / 板块 / 个体 …）
│    否 → 现金分成明细为空或无可分配金额（如全额积分支付）
│
└─ 现金消费且积分返比 > 0？
     是 → 按四项比例返积分
          （业主 / 商家 / 物业币 / 建设积分池）
     否 → 无返积分（比例为 0，或非现金消费场景不触发）

建议联调用例

# 操作 期望
1 微信/现金下单 → 完成 → 看统筹「分成明细」 出现可分配金额与各级金额
2 提高平台订单分成 → 再下一单 平台金额变大，四级按权重压缩
3 参数里把积分四项设为非 0 并审批通过 → 现金消费完成 住户积分 / 建设积分流水有入账
4 全额积分支付完成一单 一般不应指望现金分成记录；也不应把「花积分」当成「积分分成」

十一、关键字段速查

老板口径 A 与现网字段映射

老板目标：可分配金额 → 物业 30% + 平台盘 70%；平台盘内我们公司占 10%（总约 7%），统筹/个体待定，周总兜底。

现网落库：先抽 platformShareRate（管理端文案「我们公司」，建议 7%），剩余再按物业 / 统筹池；板块从统筹池抽（兼容项，建议 0%）；统筹实得展示为「统筹/周总」。

注意：「先抽 7% 再对剩余 30/70」与「先 30/70 再从盘内抽 10%」不完全等价；精确对齐需后端改算法。现金四级比例仅平台管理员可改（参数页收口）。

现金 / 平台
