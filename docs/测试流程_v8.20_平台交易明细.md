# 测试流程 — v8.20 平台交易明细（平台管理员私有）

> **版本**：2026-10-25 · 对照 `API接口文档_v8.12(2).md` §106 +《前端交付_平台交易明细_v8.20》
> **被测前端**：邻里商城服务管理端（本仓库）
> **被测页面**：`src/views/admin/PlatformTransactions.vue` · 路由 `/platform-transactions` · 菜单「平台交易明细」
>
> **核心口径（务必先读，测错方向等于白测）**
> 1. **仅 `platform_admin`**。物业管理员、统筹、物业操作员一律不可见；不新增权限码，**不能通过授权开放**。后端已硬校验 403 / 20004，前端隐藏入口只是体验优化。
> 2. **金额永不为负**，收/支由 `direction` 决定，不要靠数值正负判断。
> 3. **不同 `unit` 不可相加**：元 / 积分 / 物业币 / 定向余额必须分行展示。跨单位求和 = Bug。
> 4. **一笔已退款的支付会有两行**：`payment` 收入行 + `refund` 支出行，这是总额口径，**不是重复数据**，禁止在前端合并或去重。
> 5. 本功能**全程只读**，不写库、不触发提现/分账/退款。

## 10. 接口层直验（UI 之外补一刀）

先拿平台管理员 token（登录后在 Application → Local Storage 或 Network 里取），然后：

```bash
# 全部物业 · 近 30 天应能看到两家物业的流水
curl -H "Authorization: Bearer <platform_admin_token>" \
  "https://test.yuanxusoftware.top/api/v1/admin/transactions?page=1&pageSize=20"

# 只看 A 物业
curl -H "Authorization: Bearer <platform_admin_token>" \
  "https://test.yuanxusoftware.top/api/v1/admin/transactions?propertyCompanyId=pc_A&page=1&pageSize=20"

# 总览：确认 groups[] 按 group+unit 拆分、categories[] 完整、trend[] 有按日数据
curl -H "Authorization: Bearer <platform_admin_token>" \
  "https://test.yuanxusoftware.top/api/v1/admin/transactions/overview?startDate=2026-09-25&endDate=2026-10-25"

# 导出：确认响应头
curl -i -H "Authorization: Bearer <platform_admin_token>" \
  "https://test.yuanxusoftware.top/api/v1/admin/transactions/export?startDate=2026-09-25&endDate=2026-10-25"
# 期望响应头：Content-Type: text/csv;charset=UTF-8、X-Export-Rows、X-Export-Truncated

# pageSize 超限时
curl -H "Authorization: Bearer <platform_admin_token>" \
  "https://test.yuanxusoftware.top/api/v1/admin/transactions?pageSize=101"
# 期望：10003

# 权限（换成物业管理员 token）
curl -H "Authorization: Bearer <property_admin_token>" \
  "https://test.yuanxusoftware.top/api/v1/admin/transactions"
# 期望：403 / 20004
```

## 12. 判 Bug 速查

| 现象 | 先怀疑 |
|------|--------|
| 选「全部物业」却只有一家物业的数据 | `src/api/request.ts` 的 `/admin/transactions` 白名单没生效 → 查 Network 请求 URL 里有没有 `propertyCompanyId` |
| 导出没有截断提示 | 跨域响应头未暴露 `X-Export-Truncated`（先确认是 dev 还是生产环境） |
| POINT 出现小数 / 与元相加 | `formatAmount` 单位分支走错，或某处直接对 `groups[]` 做了跨 unit 求和 |
| 表格 key 重复告警 | 退款双行 id 相同，rowKey 去重逻辑被改动过 |
| 物业管理员能看到数据 | 后端未部署 v8.20 的硬校验，或前端路由 roles 配错 |
| 登录/刷新频繁 401 | v8.16–v8.19 起旧 token 失效，**重新登录一次**（见 0.5） |
