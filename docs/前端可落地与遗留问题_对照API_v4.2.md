# 前端可落地项与遗留问题（对照 API v4.2）

> **日期**：2026-08-01（修订：积分兑换比不按需求 1:1，以管理端自主配置为准）  
> **对照**：`API接口文档_v4.2.md`（文内标注版本 v4.1，最后更新 2026-07-31）  
> **原则**：后端契约已具备 → 仅改前端落地；需后端 / C 端 / 产品拍板 → 记入遗留表

---

## 一、产品口径更新

| 议题 | 口径 |
|------|------|
| 积分兑换比 | **不参考**需求文档「1 元 = 1 积分」。比例由物业在 **参数配置 → 积分兑换比例** 自主调整；订单侧以商家挂接配置为准。 |
| 咨询入口 | 对应需求「删除中间咨询层」；管理端入口已下线，后端 §58 仍在（见遗留 R08）。 |

## 三、遗留问题（整理后）

### 3.1 需后端改动

| ID | 模块 | 问题 | 现状 | 期望 |
|----|------|------|------|------|
| R01 | 服务询价 | 报价仍走表单，需求要聊天发价 / 订单链接 | §57 / §67 为表单接口；会话有 `service_request` | 聊天内报价契约，或明确表单为正式方案 |
| R02 | 统筹 / 板块 / 区域提现 | 缺对应提现门户与接口 | 仅有个体负责人、快递员等提现 | 补齐提现 API + 角色权限 |
| R03 | 统筹住户权限 | 可查看住户、不可删、不可冻币 | 住户管理仅在物业端 | 统筹只读住户 API / 权限约定 |
| R04 | 板块 → 区域 | 板块可加区域负责人；区域独立工作台 | 区域/项目仅在物业 `RegionalLeaders` CRUD | 板块端入口 + 区域角色门户（若需要） |
| R05 | 住户排序 | 按楼层参与排序 | 仅 `building,unit,room` | 扩展 `floor` 或约定从房号解析 |
| R06 | 物业费账期 | 「自×日起至×日到期」展示 | 有欠费笔数/金额，无统一起止字段 | 列表/详情补 `feeStart`/`feeEnd`（或等价字段） |
| R07 | 商家权重 | `levelWeight` 物业是否可调 | 仅 `rankOrder` 可编，`levelWeight` 只读 | 确认可否写入；不可则维持只读 |
| R08 | 咨询模块 | 前端入口已删 | §58 接口与表仍在 | 择机 deprecate 或保留给历史数据 |
| R09 | 图片上传 | 活动组封面 / 商品图多为 URL 文本 | 缺统一上传或未接 | 上传接口 + 前端组件 |

### 3.2 需产品拍板（规则未定或与实现冲突）

| ID | 模块 | 问题 | 说明 |
|----|------|------|------|
| P01 | 积分规则 | 「积分仅可兑物业币、不可直接冻结积分」 | 现有冻币、`pointToFeeRate` 抵物业费是否保留，需一句话定稿 |
| P02 | 配送价格区间 | 是否仍挂物业菜单 | API §62 仍是物业 CRUD；与「物业不管配送价」表述冲突——保留 / 迁平台 / 只读三选一 |
| P03 | 服务入驻接单 | 入驻后是否直接接单 | 后端已约束：审核通过且 `active` 可接；若还要类目开通等需补充 |
| P04 | 技工能力边界 | 是否要对齐全套商家能力 | 已有技工档口 + 服务/提现；无商品/广告/关键词全套 |

## 四、已对齐、无需当遗留

官方推荐、币使用条件、自动提现周期与阻止提现、建设积分、资料奖励（物业）、公司账户、欠费报表/催缴、楼宇结构、价格审批、四项分成≤30%、配送范围与距离、支付后自动进配送大厅、积分趋势/消耗结构、活动组课时价、**积分兑换比例由参数配置自主调整**。
