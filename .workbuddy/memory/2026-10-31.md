## 全链路文档：下单 → 支付 → 分账 → 提现到账（17:xx）

**产物**：`docs/全链路_下单到分账到提现到账_20261031.md`

**依据**：`docs/API接口文档_v8.25` §8（订单/支付/核实）、§21（分账/钱包流水）、§51.10-51.13（物业结算提现）、§60.13-60.15（业主小店件数制）、§70.5-70.7（多角色提现）、§97（电商收付通）、§99（楼长/卖货钱包）+ 本仓 `Param.vue` / `services.ts` / `PlatformShareConfig.vue`。

**核对出的关键事实（后续别记错）**
- **分账记账线 ≠ 微信资金线**。`distribution_records` + `wallet_flows` 是账本；真实资金走电商收付通：住户付款直连商家 `sub_mchid`，平台只分走佣金 + 配送费，剩余货款 `finish` 时解冻给商家。
- **四层分成树（物业/统筹/板块/个体）不走微信分账**，由平台佣金到账后走「微信商家转账（新版）」出款，属平台内部结算。
- **提现是人工打款**：`auditResult=completed` 时后端只写 `disburseChannel=manual` + `disburseStatus=success` + `transferProof`，系统不发起转账。`auto_cbk` 通道未启用，文档两处明说占位代码已移除。
- **结算触发点是确认收货**（`completed` = 资金终态，之后不可退）。配送员点送达只写 `deliveredAt`，订单停在 `delivering`；补了 `OrderAutoConfirmScheduler` 每小时兜底（超售后窗口默认 3 天自动完成）。
- **配送员收入与订单结算无关**：`deliveries/{id}/complete` 成功即入账 `courier_delivery_income`。
- **配送口径 v8.9**：`courierEarning = deliverySettlementBase × (1 − platform_delivery_share_rate)`，`deliverySettlementBase = 实付配送费 + 配送补贴`；`courierShare ≡ courierEarning`；`delivery_rules.courier_per_order` 已不参与。
- **楼长分成从 `propertyShare` 里扣**（守恒），下单时快照 `orders.building_leader_id/rate`，换楼长不影响旧单。
- **业主小店走件数制**，跳过 `DistributionService`：一级代理货款 `distributor_wholesale_income` + 店主差价 `reseller_profit`，不参与四层分账。

**核对出的文档矛盾（已列待确认）**
1. 平台盘三档：B 方案写 1:6:3（property 60%），§99 写「有统筹时 `property_share = 可分配金额 × propertyRate`，默认 0.30」。差一倍，需以接口实际返回为准。
2. `pointToFeeRate`（积分抵现率）消费方未明确。
3. 物业领导预设是否含 `coin:display_control`（否则参数页物业币展示开关不渲染）。

**参数配置对接结论**：写通道已闭环可验收；但 `platformDeliveryShareRate` 在「平台分成配置」页（`PUT /admin/platform-share-rates`）、`commissionRate` 在商家挂接/价格审批，两者都不在参数配置页 —— 验收常找错地方。`deliveryBaseFee` 无计费消费方（仅利润测算参考）。

## 全链路测试前置清单（21:xx）

**产物**：`docs/全链路测试前置_各角色准备清单_20261031.md`（13 节，含逐角色表 + 卡点速查 + 一页 checklist）

**新发现（重要，测试前必看）**：积分/物业币停用的拒绝码有**两套口径并存**
- 旧码：`40003`（积分停用）/ `50006`（物业币停用）—— 接口文档 §5.x、§21154 仍写着，前端码表也还留着
- 新码：`97070` / `97071` —— 后端 2026-10-30 回复刚给，前端已补
- 测试第一条应先探实际返回哪个码，否则会把「新码没部署」误判成「97070 不生效」

**其他测试前置要点（写进清单的事实）**
- 商家挂接配置缺失 → 下单/支付 `60006`，是最常见卡点；入驻审核通过会自动建，但老商家可能没有
- 商家微信进件必须到 `finished`（`legal_validating`/`signing` 的链接有时效，不点永远到不了终态），否则只能积分/物业币支付（`99004`）
- 楼长是「住户+楼长」复合身份，测试不要新建 `role=building_leader` 账号；楼长必须与买家**同小区同单元**，否则下单快照为空、`buildingLeaderShare=0`
- 四层树（统筹/板块/个体）与商家都要绑收款账户（`POST /admin/cbk/accounts`，`ownerType` 分 6 种），否则记账有钱但打不出去
- 配送员需微信侧 openid 收款授权
- 物业币充值在 `coinEnabled=false` 时被拒 → 测「关掉后被拒」必须**先充再关**
- 业主小店：申请 active → 缴保证金（默认 500）→ 从一级代理拿货（扣库存件数）→ 零售价 ≥ 进货价；`listingId != null` 的订单**跳过四层分账**，查 `distribution_records` 找不到四层数据属正常
- 一级代理需 `is_distributor=1`，货源设 `wholesalePrice`/`stock`（库存=件数）
